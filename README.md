# 美国西岸之旅 · 实时行程助手

一个移动端优先的单页旅行助手，所有行程数据来自 `travel-data.json`。

仓库：https://github.com/kojimaakari11-dev/uswest
线上：Cloudflare Pages（静态托管，无构建步骤）

## 页面功能

| 模块 | 说明 |
|------|------|
| **下一站** | 按当前时间自动推算下一个行程点：大字标题、类型图标、预计时间 + 实时倒计时、详细地址、备注；三个按钮「怎么去 / 详情 / 刷新」；卡片底部列出接下来的 2-3 个行程 |
| **每日行程** | 顶部横向日期滑动条（默认选中今天；未出发时默认出发日）+ 右侧「全部串联」按钮。下方是该日行程的虚线时间轴，每两点之间标注交通方式与预估耗时；点行程点弹出底部弹窗（详情 + 导航）。**航班类行程压成单行**，备注与按钮收进弹窗；每个行程点右上角有勾选框，勾掉代表已走过 —— 该点从当天列表和顶部「下一站」中一并隐藏，当天列表底部出现「已收起 N 项 · 点击展开」可回看或取消 |
| **种草的打卡地** | 从小红书等渠道收集的打卡地卡片，点开可看地址、最佳时间与来源链接 |
| **预订与购票** | 已确认的餐厅、门票 |
| **航班行程** | 横向滑动深色卡片，共 4 张：①上海→首尔→旧金山 ②旧金山↔伯班克 ③圣何塞↔波特兰 ④旧金山→首尔→上海。卡片顶部 `FLIGHT 01/04` 与航司名，中部大号机场代码（中转 3 列 / 往返 2 列）与时间，底部实时倒计时「距离起飞还剩 X天 HH:MM:SS」。底部圆点指示器 + 右上角页码 |
| **旅行准备** | 分类清单，支持在网页上直接添加 / 删除事项，标题右侧显示「已完成 / 总数」进度条。勾选与增删存浏览器本地；数据源的清单条目变动时会自动迁移，已勾状态不丢 |
| **JSON 编辑器** | 页面右下角 ⚙️ 按钮可直接编辑全量数据，改完可下载回写 |

## 网页上的改动存在哪里

网页上勾选、添加、删除都不会写回 `travel-data.json`，只存在当前浏览器的 localStorage 里：

| 键 | 内容 |
|---|---|
| `uswest.checklist.v2` | 准备清单的条目与勾选状态 |
| `uswest.doneActs.v1` | 「已走过」的行程点（键为 `日期\|原始时间\|标题`，所以改 JSON 里的其他内容不会把勾选弄丢） |

换设备、换浏览器或清理浏览数据会丢失这些记录；清单可用「恢复默认清单」重置。清单条目在 `travel-data.json` 里增减时，已勾状态会自动迁移。

## 部署到 GitHub + Cloudflare Pages

### 1. 创建 GitHub 仓库

1. 登录 https://github.com
2. 点击右上角 **+ → New repository**
3. 仓库名填写 `uswest`（或任意名称）
4. 选择 **Public**
5. 点击 **Create repository**

### 2. 上传文件

在仓库页面：

1. 点击 **Add file → Upload files**
2. 上传以下文件：
   - `index.html`
   - `travel-data.json`
   - `README.md`
3. 点击 **Commit changes**

### 3. 连接 Cloudflare Pages

1. 登录 https://dash.cloudflare.com
2. 进入 **Pages → Create a project**
3. 选择 **Connect to Git**
4. 选择刚才创建的 GitHub 仓库
5. 框架预设选择 **None**
6. 点击 **Save and Deploy**

部署完成后，Cloudflare 会给你一个 `.pages.dev` 结尾的网址，可以直接分享给朋友。

## 更新数据

### 方式一：直接改 GitHub 上的 JSON（推荐）

1. 打开 GitHub 仓库
2. 点击 `travel-data.json`
3. 点右上角铅笔图标 ✏️ 编辑
4. 修改后点 **Commit changes**
5. Cloudflare 会自动重新部署，约 1-2 分钟后刷新网页即可

### 方式二：用网页编辑器

1. 打开部署好的网页
2. 点右下角 **⚙️** 按钮
3. 编辑 JSON 内容
4. 点 **下载 JSON** 保存到本地
5. 上传到 GitHub 替换原文件

## 数据字段说明

必填字段见 `travel-data.json` 各对象本身。以下可选字段会影响页面展示：

| 字段 | 位置 | 说明 |
|------|------|------|
| `meta.tripTimezone` | 顶层 | 行程所在时区（IANA 名称），默认 `America/Los_Angeles`。所有没写 `tz` 的时间都按它解析 |
| `daily[].activities[].tz` | 行程点 | 该时间的时区。**跨时区航班当天务必填写** —— 例如 9/24 从浦东起飞写 `Asia/Shanghai`，仁川中转写 `Asia/Seoul`，抵达旧金山写 `America/Los_Angeles`。不填会按行程时区解析，导致顺序错乱 |
| `daily[].activities[].leg` | 行程点 | 「从这里去下一个点」的交通方式和耗时，纯展示文本，如 `"✈️ 飞行 1h50m"`。不填则按两地坐标自动估算驾车 / 步行时间 |
| `daily[].activities[].address` | 行程点 | 详细地址，用在「下一站」卡片和详情弹窗。不填则回退显示 `location` |
| `flights[].title` | 航班 | 航班卡片标题，如 `"上海 → 首尔 → 旧金山"` |
| `airports` | 顶层 | 机场代码 → `[纬度, 经度]`，给航班行程点提供导航落点。不改的话用内置的 PVG/ICN/SFO/BUR/SJC/PDX |
| `hotspots[].sourceUrl` | 打卡地 | 小红书等来源链接 |

### 关于时间写法

- 行程点的时间写 `"HH:MM"`（如 `"13:10"`）表示精确时间，会显示实时倒计时。
- 也可以写模糊时段：`凌晨 / 清晨 / 早上 / 上午 / 白天 / 中午 / 午后 / 下午 / 傍晚 / 黄昏 / 晚上 / 夜里 / 夜间`。页面按大致时段排序，但**只显示时段文字本身，不会推算并显示具体钟点，也不挂倒计时**。**同一天内的先后以 JSON 里手写的顺序为准**，不会因为模糊时段被打乱。
- 「入住」这类常规动作不必写进行程，只写「退房」即可 —— 每晚住哪已经在「每日行程」标题下方单独显示。
- `"全天"` 表示占位说明（例如「待安排」），不参与「下一站」推算，但会正常显示在当天时间轴里。
- 航班时间的时区必须写成带偏移的完整 ISO（如 `"2026-09-25T10:35:00-07:00"`），页面直接取其中的挂钟时间显示。

## 隐私提醒

仓库是公开仓库，`travel-data.json` 会被所有人看到。**请勿写入**：

- 护照号 / 身份证号
- 信用卡号
- 机票或酒店的确认号、订单号
- 座位号
- 真实姓名全拼
- 手机号

页脚也放了一句同样的提醒。旅途中如需记录这类信息，请另存到本地笔记，不要放进这个仓库。
